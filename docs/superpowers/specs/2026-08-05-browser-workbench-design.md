# 浏览器工作台（新标签页插件）设计文档

> 日期：2026-08-05
> 状态：设计已确认，待用户审阅
> 关联项目：参考 FinTracker（github.com/syh190819/FinTracker，dev 分支）的记账逻辑与视觉风格

---

## 一、背景与目标

用户希望做一个浏览器插件：安装后，浏览器新建标签页变成插件自带的工作台页面，作为日常使用的起始页。

工作台包含：搜索、快捷跳转、记账、便签、待办、体重管理、疼痛日记、食材统计、采购清单、计划菜谱等模块。数据全部存储在浏览器本地，不依赖服务器；插件会分享给他人使用，安装后开箱即用、各人数据互不干扰。

记账模块的业务逻辑（收支类型、分类、预算、统计）参考 FinTracker，但数据层改为本地存储。

## 二、范围与边界

### 本期范围

- Manifest V3 浏览器扩展，接管新标签页（Chrome / Edge）
- 工作台首页 + 各功能完整页面
- 全部数据本地存储（IndexedDB + chrome.storage.local）
- 数据整体备份导出 / 恢复导入
- 构建产物打包为可分享的压缩包

### 不在本期范围

- 服务器端账号、云同步、多端同步
- Chrome 商店 / Edge 商店上架
- 浏览器系统级通知（首页内提醒即可，接口预留）
- 站内搜索的具体实现（搜索模块预留扩展位）
- 手机端深度适配（桌面优先，窄屏可用即可）

## 三、整体布局与视觉

### 工作台首页

- 顶部：搜索栏 + 设置入口
- 中部：快捷跳转图标网格（分组展示）
- 下部：概览卡片区
  - 本月收支（总额、预算进度）
  - 待办（未完成数量、今日到期、最近 3 条）
  - 体重（最新记录、趋势迷你图、今日未记录提醒）
  - 疼痛（最近记录、最近 7 天程度变化）
  - 食材（临期提醒、缺货提醒）
  - 采购清单（未完成项）
- 右下角：FAB "+" 快速操作（记收入 / 记支出 / 新建便签 / 新建待办 / 加购物项）

### 功能页面

顶部导航进入：记账、体重、疼痛日记、食材、菜谱、采购清单、便签、待办、设置。

### 视觉风格

- 主色深海军蓝 `#1a1a2e` + 灰白极简，与 FinTracker 一致
- 卡片式布局、圆角、留白克制
- 桌面为主，窄屏（375px）下卡片单列、导航收进抽屉

## 四、功能模块

### 1. 搜索

- 顶部搜索框，回车打开新标签页进行搜索
- 内置引擎：百度、必应、谷歌，可切换默认引擎
- 支持自定义引擎（名称 + 搜索 URL 模板，`{q}` 占位）
- 引擎以配置数组维护，站内搜索（如 B 站、抖音）后续只需增加一条配置即可接入

### 2. 快捷跳转

- 分组网格展示网站图标，默认分组"常用"
- 预置常用网站：抖音、B 站、微博、知乎、淘宝、京东、百度、微信读书等
- 添加网站：填写名称 + 网址，自动抓取网站图标；抓取失败回退为"首字母图标"
- 分组：可新建、重命名、删除分组；图标可在组内拖拽排序
- 图标、分组数据本地保存

### 3. 记账（对齐 FinTracker）

- 收支记录：类型（收入 / 支出）、金额、分类、日期、备注
- 分类管理：预置常用分类，可增删改；收入、支出分类分开
- 月度预算：可设每月总预算，也可按分类设置预算
- 统计图表：
  - 本月收支汇总
  - 月度支出趋势（折线）
  - 分类支出占比（饼图）
  - 预算 vs 实际（柱状图）
- 快速入口：FAB 一键"记收入 / 记支出"
- 数据随整体备份导出 / 恢复

### 4. 便签

- 卡片式便签：文本内容、可选颜色、可置顶
- 支持新建、编辑、删除
- 置顶便签排在最前

### 5. 待办

- 每条待办：标题、日期（可选）、完成状态
- 勾选完成，未完成优先排序，按日期先后排列
- 支持编辑、删除

### 6. 体重管理

- 每日体重记录：日期、体重（kg）、备注
- 趋势曲线图，叠加目标体重参考线
- 目标体重设置，BMI 计算（需在设置中填写身高）
- 首页提醒：开启提醒后，若当天未记录则提示"今天还没记录体重"

### 7. 疼痛日记

- 每条记录：时间、部位、疼痛程度（1-10）、诱因、备注
- 历史记录列表，可按时间倒序查看
- 统计：疼痛程度随时间变化（折线）、部位出现频次

### 8. 食材统计

- 食材库存：名称、数量、单位、保质期（可选）、分类（蔬菜 / 肉蛋 / 调料 / 主食 / 其他）
- 统计：库存总数、分类分布、临期提醒（3 天内到期 / 已过期）、缺货（数量为 0 或低于阈值）
- 支持新增、编辑、删除、增减数量

### 9. 采购清单

- 清单项：名称、数量、单位、完成状态
- 来源标记：手动添加 / 菜谱联动 / 库存不足自动加入
- 勾选"已购买"后，弹出确认"补回食材库存"：对应食材数量增加，无该食材则新建

### 10. 计划菜谱

- 菜谱库：菜名、食材清单（食材名 + 数量 + 单位）、做法步骤、份量（可选）
- 按日期安排菜单（一天可安排多餐 / 多道菜）
- 联动：将安排的菜标记"已做"后，按食材清单自动扣减库存

### 11. 联动逻辑

- 做菜扣库存：标记"已做" → 逐项扣减对应食材数量
  - 库存不足时给出提示，可一键把缺口加入采购清单
- 缺货提醒：首页与食材页展示缺货食材，一键加入采购清单
- 采购入库：勾选采购项已买 → 确认后补回库存

### 12. 设置

- 默认搜索引擎
- 主题（深海军蓝默认；浅色主题为后续扩展位）
- 身高（用于 BMI）、目标体重、体重提醒开关
- 数据备份：整体导出 JSON 文件 / 从文件恢复
- 危险操作：清空全部数据（需二次确认）

## 五、数据模型（本地 IndexedDB）

所有表均含 `id`、`created_at`；删除采用软删除（`deleted_at`）或物理删除视场景决定（列表类可物理删除，账目类建议软删除）。

| 表 | 字段 |
|:--|:--|
| `expense_categories` | id, name, type(income/expense), sort, deleted_at |
| `expenses` | id, type(income/expense), amount, category_id, date, note, created_at, deleted_at |
| `budgets` | id, month('YYYY-MM'), category_id(空=总预算), amount |
| `notes` | id, text, color, pinned, created_at, updated_at |
| `todos` | id, title, due_date, done, created_at |
| `link_groups` | id, name, sort |
| `links` | id, group_id, name, url, icon_url, sort |
| `weight_records` | id, date, weight_kg, note |
| `weight_settings` | 单行: goal_kg, height_cm, remind_enabled |
| `pain_entries` | id, time, part, level, trigger, note |
| `ingredients` | id, name, quantity, unit, category, expiry_date, updated_at |
| `shopping_items` | id, name, quantity, unit, done, source, created_at |
| `recipes` | id, name, ingredients(JSON: [{name, quantity, unit}]), steps, servings, created_at |
| `meal_plans` | id, date, recipe_id, status(planned/cooked), cooked_at |
| `settings` | key/value：默认引擎、主题、身高、目标体重、提醒开关等 |

金额以"元"数值存储，展示时保留两位小数。

## 六、技术方案

### 扩展层

- Manifest V3：`chrome_url_overrides.newtab` 指向构建产物首页
- 权限最小化：仅 `storage`
- 图标抓取：使用 favicon 服务 URL；失败回退首字母图标（不需要主机权限）

### 前端

- Vite + React + TypeScript（与 FinTracker 前端技术栈一致，便于后续互通）
- 图表：recharts（与 FinTracker 一致）
- 拖拽排序：HTML5 原生拖拽（快捷跳转图标排序等）
- 无远程代码 / 无 CDN 依赖，全部本地打包，符合扩展安全要求

### 数据层

- IndexedDB：业务数据（记账、便签、待办、链接、体重、疼痛、食材、采购、菜谱、菜单）
- chrome.storage.local：轻量设置项
- 统一封装数据访问层（db 模块），页面不直接操作 IndexedDB

## 七、错误处理与可靠性

- 数据库打开失败：给出明确提示，不静默
- 金额 / 数值输入：前端校验，非法值阻止提交
- 图标抓取失败：回退首字母图标
- 备份导入：校验 JSON 结构与版本号，格式不符时中止并提示，不覆盖现有数据
- 所有写操作返回成功/失败状态，失败时提示用户
- 软删除账目：避免误删不可恢复

## 八、打包与分享

1. `npm run build` 生成 `dist/`
2. 压缩 `dist/` 为 zip 包，可发给他人
3. 安装方式（Chrome / Edge）：
   - 打开 `chrome://extensions`（Edge 为 `edge://extensions`）
   - 开启"开发者模式"
   - 点击"加载已解压的扩展程序"，选择解压后的目录
4. 上架商店为后续事项（需开发者账号）

### 共性不足（也是本项目的差异化机会）

1. 同类项目几乎都是"导航 + 效率 + 个性化"定位，**没有把记账、健康（体重/疼痛）、饮食（食材/菜谱/采购）整合进新标签页**。
2. 数据备份/导出能力普遍薄弱（多为 localStorage，无备份入口）；本项目已有 JSON 全量备份，并补充记账 CSV 导出。
3. 图标与壁纸依赖外网服务（Google favicon、壁纸 API），国内网络体验差；本项目补内置常用站图标库，背景支持纯色/渐变/图片 URL。
4. 搜索大多只支持少量引擎；本项目预置常用站内搜索（B站/抖音/知乎/淘宝）并支持自定义 `{q}` 引擎。
5. 主题与个性化（深/浅色、背景）几乎是标配；本项目新增浅色主题与背景设置。
6. 性能与隐私是共同卖点：本项目保持无远程代码、权限最小化、bundle 轻量。
